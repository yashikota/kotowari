# Ablation

少数の機能を全方位から磨く。実験の作業場は `adr/NNNNN/experiments/` である。kotowari はベンチを回さない。比較実験はエージェントがこのディレクトリで行う。

評価関数を間違えると、探索は猛烈に間違った方向へ進む。与えた指標だけを最適化して、本当に欲しい性質とずれた解を出したら棄却する。これはカメラの collapse と同じ失敗である。

## 手順

1. 評価関数を先に書く。定量だけでなく、保守性・運用・セキュリティなどの定性も含める
2. 候補を列挙し、`adr/NNNNN/experiments/` に PoC を置く
3. 比較実験する。自分で測れないときは他人の実験を引用する。**比較も引用もない決定は禁止**
4. 結果・棄却理由・受容したトレードオフを日本語 README に残す
5. `accepted` のとき英語 `PUBLISH.md` を書く。kotowari は翻訳しない
6. 実装仕事は ISS に切り、ADR と相互リンクする

ADR は削除しない。番号は RFC と同じく追記する。判断をやり直すときは新しい ADR を書き、旧 ADR を `superseded` にして `supersedes` で指す。

空の ADR を作った時点で、問い / 評価関数 / 候補（良い点・中立・悪い点） / 実験 / 結果 / 決定（選んだ候補、良い点と悪い点、確認） / 前提の骨格がある。先に評価関数を埋める。比較のない決定は、候補の賛否が空のまま `accepted` にしたときである。

Issue 配下は実験砂場にしない。
